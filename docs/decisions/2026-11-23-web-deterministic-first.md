# 网页控制：确定性与纯代码优先（2026-11-23，老板拍板）

## 原则

**能不用模型就不用模型。** 网页任务的定位、点击、输入、校验都要由程序计算完成；
模型只在两种情况下出现：

1. 第一次探索页面、把流程写进经验库；
2. 执行器卡住（找不到 / 命中多个 / 校验失败）时，由模型或人来判断怎么修。

日常重跑一条已保存的路径，**模型调用次数应当是 0**，消耗只有本地计算时间。
理由:DOM 是结构化的，匹配是规则计算，不是"理解"；交给模型只会更慢、更贵、更不稳。

## 落到实现上的硬要求

1. **定位在程序里做**：`web_find(text)` / `web_click({text})` / `web_type({text, value})`
   由页面内的规则匹配完成任务，模型只给"目标名字"，不传坐标。
2. **判定必须唯一**：命中 1 个才执行；命中 0 个或 ≥2 个一律停止并回报候选，绝不猜。
3. **每步都要校验**：`expect`（文字出现 / URL 变化 / 元素出现）没满足就算失败，
   不允许"点完就当成功"。
4. **默认 dry-run**：执行器先报告"每步会点哪个控件"，人确认后才允许真跑。
5. **遍历要全**：主文档 + 所有 iframe + 递归 open shadowRoot，跨域帧同样处理。
6. **失败即停**：任何一步不满足就停下来，附现场（URL、命中候选、截图路径），
   由模型或人修路径；不允许跳过步骤继续跑。

## 不允许的

- 用模型去"看着页面猜要点哪"来完成已保存的流程（键鼠模式才需要那样）。
- 未经 `expect` 校验的步骤进入下一步。
- 在命中不唯一时自行挑选一个。

## 与能力阶梯的关系

这就是预设阶梯第 3 级（网页 DOM）的正确用法：网页任务走 DOM 通道，
键鼠只是"网页读不到时"的降级路径（第 6 级）。
