# 网页控制层（v0 草案，2026-11-23）

状态：**仅设计，未开发**。所有决定均来自老板 2026-11-23 的拍板。

## 1. 定位

```
用户任务
   ↓
球（computer-use）
   ├── 键鼠（默认通道，永远兜底）
   └── 网页控制层（可开可关）—— Playwright MCP 操作浏览器
```

边界：不改 DSH 官方架构。只用官方 `@deepseek-ai/dsh-mcp-client`（纯配置）挂我们自管的 MCP server，工具以 `mcp__web__*` 出现在模型侧。

## 2. 浏览器模式

| 模式 | 谁启动 | profile | 说明 |
|---|---|---|---|
| `chromium` | 我们（Playwright MCP） | 我们指定的 persistent 目录 | 固定稳定版本，随包分发/下载 |
| `chrome` | Playwright MCP 启动系统 Chrome | 我们指定的 persistent 目录 | 路径必须由操作者手选，**禁止自动发现**；不碰用户日常 Chrome 的标签与配置 |
| `attach` | 用户自己启动的 Chrome | 用户的 | 仅连接已开的实例（用户自己带调试端口），我们绝不代为启动 |

**禁止**：带调试端口重启用户的 Chrome（体验差、丢标签）。因此 `chrome` 模式 = 用他的可执行文件 + 我们的独立 profile 启动新实例。

## 3. 设置项

| 项 | 默认 | 说明 |
|---|---|---|
| 网页控制 | 关 | 总开关（本地 DSH 默认关） |
| 模式 | chromium | 上表 |
| Chromium 版本/路径 | 空 | 空 = 已装则用，否则按需下载 |
| chrome.exe | 空 | 只读展示 + "选择…"；用户没选就不启用 chrome 模式 |
| CDP 端口 | 空 | 仅 attach |
| 固定 Chromium 版本 | 内置常量 | 随发版锁定，开发一律对齐该版本 |

## 4. 路由策略（已按老板意见改写）

**默认键鼠。** 网页层不是一个"先试再说"的通道，而是**被判定为网页任务时才启用**的通道。

### 4.1 进入网页模式的判据

满足任一即视为网页任务：

1. 用户话里出现网页语义：`网页/网站/浏览器/网址/URL/http(s):///登录/表单/后台/控制台/某网站名`
2. 当前前台窗口是浏览器（窗口类名 `Chrome_WidgetWin_1` 等，或标题含 Chrome/Edge/Firefox）
3. 上一步网页通道已经激活（粘性，见 4.3）

### 4.2 环境侦测：远程/虚拟环境优先键鼠（软禁用）

**这个优先于一切。** 检测到以下任一情况，**本会话软禁用网页通道**——不是改配置，而是运行期决定：

| 信号 | 检测方式 |
|---|---|
| 远程桌面 | `SESSIONNAME` 以 `RDP-` 开头；或 `GetSystemMetrics(SM_REMOTESESSION)` |
| 虚拟机 | `Win32_ComputerSystem` 的 Manufacturer/Model 含 VMware / VirtualBox / QEMU / Xen / Microsoft Corporation Virtual Machine / Parallels |
| 远程控制软件 | 进程名匹配：SunloginClient（向日葵）/ ToDesk / AnyDesk / TeamViewer / RustDesk / Parsec / winvnc / TightVNC |
| 云桌面 | 上述 VM 信号命中且存在厂商特定进程/服务名 |

软禁用的表现：

- 设置里开关仍显示"开"，但网页通道标记不可用，原因写进会话状态与工具说明
- 模型侧看到的提示是"当前环境是远程/虚拟桌面，网页控制不可用，请用键鼠"
- 用户可显式说"这次强制用网页"作为**单次覆盖**（记录在会话里，不写配置）

### 4.3 粘性：用网页就继续网页

一旦本任务进入网页模式：

- 后续步骤只要仍是网页操作 → **继续走网页**，不每步重新判定
- 退出网页模式的条件（任一）：
  1. 需要操作的是原生桌面 UI（对话框、资源管理器、非浏览器窗口）
  2. 用户明确要求用键鼠
  3. 网页通道失败（见 4.4）

### 4.4 失败与回退（稳妥）

- 网页工具返回同类失败**一次**（`isError`、元素找不到、导航超时、页面崩溃、浏览器进程消失）→ 当场切键鼠继续该步骤
- 本任务内记"网页已降级"，不再反复试探，直到：
  - 键鼠完成该步且下一步仍是网页操作，且网页层健康检查通过（进程活着、能取 snapshot）→ 允许切回
- 全程只影响当前任务，不写全局配置；下个任务重新按设置 + 环境侦测决定

## 5. 分发与下载

- Chromium 包**上传到 GitHub release**，从该链接下载；**不用官方 CDN**
- 下载后 **sha256 校验**；失败重试一次，仍失败则提示"请选系统 Chrome 或稍后重试"
- 下载在后台，不阻塞 DSH 启动；未完成时网页通道显示"准备中"
- **版本固定**：与我们发版绑定的一个稳定版本，后续开发全部针对它，不随上游漂移

## 6. 生命周期

```
启动 → 读设置 → 关：什么都不做
            → 开：环境侦测 → 命中远程/虚拟 → 软禁用（键鼠）
                            → 未命中 → 解析浏览器 → 起 MCP 子进程（stdio）
                                     → 起不来：日志写明原因，网页通道不可用，键鼠照旧
```
- 退出时结束我们自己启动的 MCP 子进程与浏览器；`attach` 的实例不动
- 端口冲突只提示，不杀进程

## 7. 安全（已拍板）

1. **不暴露 `browser_run_code_unsafe`**（等价 RCE），只留 snapshot/click/type/navigate 等常规工具
2. **不允许带调试端口启动用户的 Chrome**；只允许 `attach` 到用户自己开的实例
3. **固定一个稳定 Chromium 版本**，随发版锁定

## 8. 落地顺序（每步可验收）

1. 只读验证：手起 `@playwright/mcp`，确认 DSH 能列出 `mcp__web__*`（不改代码）
2. 设置卡片 + 总开关（默认关）
3. 环境侦测（远程/虚拟/远控）+ 软禁用
4. 路由层：网页意图判定、粘性、失败回退
5. chromium 模式：固定版本、下载校验、persistent profile
6. chrome 模式（手选 exe）+ attach 模式
7. 打包发版与文档
