# dsh-agi

[English](README.md)

DeepSeek Harness 的悬浮球智能体。跟它说话、把截图贴给它，让它操作你的桌面——然后让它记住你的流程到底怎么走，并且每执行一次就变得更靠谱一点。

本仓库 fork 自 [dsh-orb](https://github.com/mini-yifan/dsh-orb-cordis)（MIT，作者 mini-yifan），改名为 `dsh-agi` 并独立维护。

## 它凭什么不一样

| | |
|---|---|
| **说，不用敲** | 点一下头像开始听，说完再点一下结束。说「你好大肥鱼」唤醒并固定面板，说「退下吧」停止任务，说「大肥鱼」可在它干活时插话。唤醒词、语音识别、语音合成全部本地运行。 |
| **有人设，也有记性** | 角色卡决定每一轮由谁回答；配合经验库，同一个球在不同项目里可以像不同的专家。 |
| **经验是库，不是笔记** | 流程存成「节点库 + 各自独立的路径」。人写的文字是打底，AI 把真实执行学到的东西补在后面；人的截图始终是评判标准。 |
| **在输入框里就能维护** | 一句「帮我创建一个节点，内容是 xxx」就够了：七个经验库工具负责搜索、创建、检查、确认——而且确认是**代码强制**的，不只是提示词。 |
| **扛造的桌面操作** | 六套独立机制（见下）保证每次点击都真的落地、画面是新的、瞄的就是那个控件。 |
| **安全模式** | 你按下任何真实按键或移动鼠标，任务立刻停止；只有球自己注入的输入被忽略。停止不会结束对话。 |
| **自己的会话** | 球默认运行一个隔离的 `computer-use` 会话：它能操作桌面、使用经验库，主窗口同时保留自己的会话；也可在设置里切换为跟随主窗口最近活动过的会话。 |

## 经验库

Markdown 笔记会过期、会被跳过。`dsh-agi` 维护一个你真能长期用的库，而且设计上让「AI 自己的经验」能持续改进它，又不会覆盖你的内容。

### 节点：一步一个包

- **标题 + 人写的说明**——操作者自己的话，是 AI 每次最先读的打底。
- **AI 补充（`ai_notes`）**——只由 AI 在真实执行之后写入：坑、更准的提示、下次该盯什么。**人写的文字永远不会被改写。**
- **带来源的截图**——人的截图是**核心评判标准**，AI 截图的身份是「执行指导」；两者都存在同一个节点包里，标注 `human` / `ai`。
- **就地查看/编辑**——编辑器里人写区块和 AI 区块分开展示，你随时能看到它学到了什么，同时保留自己措辞的权威。

### 路径：看得懂的节点图

- 一条路径拥有**节点实例与边的有向图**，不是一条平铺的列表。两条箭头汇进一个节点就是汇合，两条箭头出去就是分支。
- 同一个节点可以出现多次。**重复不等于成环**：会不会绕圈取决于边，每次插入都会在实例图上做真正的环检测（Kahn 算法）。
- 画布画成圆圈加箭头，每个位置带一个显示编号（1..N）。编号每次渲染重算：同一个节点的两个实例也分得清，编号不会跳号或留空。
- 插入对话框给三个来源：本路径内已有位置、搜索结果、收藏节点。选中已有位置＝**只加一条连到那个位置的边**，不会重复加节点；选库里的节点＝新建一个位置并连线，节点本身不会被复制。
- 节点和路径都能复制（`_复制版_<时间戳>` 命名），也能导出到空文件夹（JSON + 截图 + manifest）再原样导入；id 冲突时自动换新 id，不会覆盖已有内容。
- 改一个节点，会同时改善**所有**引用它的路径——一处修好，处处生效。

### 执行之前先检查

路径支持随时检查和保存时检查：

- 引用的节点是否都还在、没被软删除；
- 每条边是否都指向本路径里的节点；
- 图是否**无环**——用真正的环检测，而不是「这个节点重复了没有」；
- 记录的起点/终点是否属于这条路径；
- 必填字段（标题、说明、截图说明）是否为空。

检查只读数据、不碰桌面。有问题的路径不可能悄悄走到真实机器上。

### 输入框驱动 + 双重约束

输入框可以通过七个工具直接维护经验库：

| 工具 | 作用 |
|---|---|
| `knowledge_graph_search` | 创建前先找已有节点/路径，候选原样交给操作者决定复用还是新建。 |
| `knowledge_graph_get_node` | 读节点，含 AI 补充、以及每张截图是人的还是 AI 的。 |
| `knowledge_graph_create_node` | 建节点；同名时**拒绝**，除非操作者明确说要新建；支持把同一条消息里附带的截图一起存进去。 |
| `knowledge_graph_create_path` | **只有在明确确认之后**才保存路径：`steps` 实例列表 + 可选 `edges`（`[from, to]` 实例下标对，缺省是一条直线）；同一节点可在不同位置重复，只有边真的绕回来才算环，成环和缺失节点会被拒绝，保存后自动检查。 |
| `knowledge_graph_check_path` | 跑静态检查，逐条报告问题。 |
| `knowledge_graph_update_node` | 修人写的标题/说明——措辞仍归操作者。 |
| `knowledge_graph_learn_node` | 真实执行后**只**更新 AI 部分：`ai_notes`（限 600 字、最多 3 条要点）和 AI 截图；没有新东西就跳过。 |

安全顺序被实现了两遍：代码拒绝未确认的写入，提示词则规定流程——先搜索、逐节点和操作者确认、最后检查并报告。创建路径时还会先明确提醒「路径创建较复杂，请务必打开经验库核对每个细节」，让操作者始终在环里，而不是被惊喜。

## 扛造的桌面操作

桌面自动化总在无聊的地方失败：弹窗占着窗口时点下去、截图还是改动前的帧、窗口移动或副屏 DPI 不同导致坐标偏了。Windows 层借鉴了 [Windows-MCP](https://github.com/CursorTouch/Windows-MCP) 的六个工程思路，把每种失败变成模型看得见的信号：

| 失败 | `dsh-agi` 的做法 |
|---|---|
| **点进被阻塞的窗口** | **动作回执**。点击前原生层会报告「前台被禁用且存在子对话框」，调用返回结构化的弹窗警告和真实选项（`press-esc` / `focus-modal` / `ask-user`），而不是盲目点下去。 |
| **「这一下到底有没有生效？」** | **动作后校验**。动作之后重新采样同一目标，记录四件事：焦点是否保持、前台是否稳定、目标是否变为禁用、窗口是否移动到足以让坐标失效。 |
| **画面是旧的** | **帧新鲜度 + 兜底截图**。每次截图前跑 `DwmFlush`，保证拿到的是合成后的帧；BitBlt 失败或全黑时切到 `PrintWindow(PW_RENDERFULLCONTENT)`；兜底帧再退化也会返回原始位图加追踪信息，不会抛异常把截图弄丢。 |
| **看着对准了、其实没中** | **悬停探测**。预览阶段把指针移上去前后各截同一小块，报告控件是否真的响应——带容差的像素差分，抗锯齿和亚像素抖动骗不了它。 |
| **屏幕/DPI 不对** | **显示器清单**。按 per-monitor-v2 DPI 感知枚举每块屏的物理和逻辑矩形；一次换算完成「归一化坐标 → 窗口矩形 → 所在屏 → 物理像素」，并把清单写进观察信封。 |
| **「读不到」被当成「没有」** | **三态观察 + 文本卫生**。每个字段都是 `provided` / `empty` / `unsampled`（权限、超时、不支持），读失败绝不会伪装成空界面；所有给模型的文本都会清洗：私用区移除、零宽字符剔除、孤立代理修复、换行转义、截断显式标注。 |

观察光晕（AI 接管时画的边框）通过 `WDA_EXCLUDEFROMCAPTURE` 从所有截图里排除，永远不会污染模型看到的画面。

## 版本记录

每个版本单独一节，最新的在最上面，方便直接对比「上一版到这一版改了什么」。

### 0.6.18

- **修复全新安装后启动崩溃**：语音子进程 `dist/voice/child.js` 静态引用 `pinyin-pro`，TTS 还会用 `sherpa-onnx-node`、回声消除用 `node-cpal`，但这三个包没写进包清单。开发机上因为工作区装过所以看不出，用户干净安装后语音子进程直接 `ERR_MODULE_NOT_FOUND`，连宿主一起被带崩（`dsh desktop host exited with 1`）。现已声明为运行时依赖。
- **修复经验库工具在 DSH 新版上注册失败**：新版要求访问 `ctx.tools` 前先声明注入，之前会打印 "cannot get property \"tools\" without inject" 并静默丢掉整个经验库工具集。`inject` 已补 `tools`。
- **发版检查新增"未声明依赖"扫描**：`pnpm release:check` 现在会扫 `dist`/`lib` 里所有裸导入，任何一个包没在 `dependencies`/`peerDependencies` 里声明就直接失败——这次这个 bug 以后在发版前就会拦下来。

### 0.6.17

- **更新器兼容 pnpm 12**：pnpm 12 会把"被忽略的依赖构建脚本"当成硬失败（`ERR_PNPM_IGNORED_BUILDS`，退出码 1），而包其实已经装好——同样的包在 pnpm 10 上只警告。安装命令现在统一带 `--config.strict-dep-builds=false` 把它降级为警告；是否真的执行构建仍由 profile 的 `allowBuilds` 决定。
- **已按真实 profile 形状实测**：`nodeLinker: hoisted` + `allowBuilds` + `minimumReleaseAgeExclude` 下，pnpm 10.30 / 11.7 / 12.15 装同一份包都成功；store 记录冲突时先报 `ERR_PNPM_UNEXPECTED_STORE`、删记录后重试成功，记录回到 profile 自己的隔离 store。
- **卸载器也认得住"搬过家"的工作区**：读 `agi-workspace.json` 的 `path`（只认绝对路径），否则用默认 `~/.dsh/dsh_agi`；它和经验库、会话留档一起进入保护清单，汇总里打印真实路径，工作区里的文件一个都不动。

### 0.6.16

- **卸载器认得住"搬过家"的经验库**：删除前先读 `agi-knowledge-graph.json` 的 `dir`（没有则读 `ACTIVE_GRAPH`），按真实位置保护；提示里打印的也是这条真实路径，不再是写死的默认目录。
- **保护路径硬校验**：经验库、球工作区、会话截图留档三处生成保护清单，任何删除项落进这些目录一律拒绝执行并报告"跳过"，不会因为以后改删除列表而误删。
- 测试补了一条：库被移到 profile 之外时仍然保留，且汇总里会写出它的真实路径。

### 0.6.15

- **自带卸载器**：插件目录里多了 `uninstall.cmd`（Windows 双击）和 `uninstall.mjs`。双击后先列出"会删什么、会留什么"，要求输入 `yes` 才动手；检测到 DSH 还在运行会直接中止，避免删到一半。
- **删得干净**：移除插件包本体、profile 清单里的 `dsh-agi` 依赖与 bundle 条目（先删加载项，半删状态也加载不起来）、语音模型与悬浮球运行时缓存、helper 缓存、插件设置（`agi-voice.json` 等）、临时日志。
- **只删自己的**：经验库（`profiles/<profile>/dsh-agi/knowledge-graph` 与 `agi-knowledge-graph.json` 绑定）、球工作区、会话截图留档、DSH 本体、其它插件、会话与附件一律不动；删除范围限定在插件目录和 `~/.dsh/dsh-agi` 内。
- **可重装**：删完照常从插件管理里重装即可，经验库自动沿用。

### 0.6.14

- **任何够新的 pnpm 都能用**：不再要求 pnpm 大版本和 profile 完全一致。只要版本 ≥ 9，应用自带 / 插件缓存 / PATH 上的都行；版本能对上记录的优先，对不上也照常装。
- **profile 用自己的 store**：每次安装都把依赖链接到 `<profile>/.dsh-agi-store/v<大版本>`，不再和用户全局的 pnpm store 绑定。用户以后把 pnpm 从 10 升到 12、或换机器，都不会再出现两边 store 互相拒绝的情况。
- **一次性自动迁移**：第一次用新 store 时会碰到 `ERR_PNPM_UNEXPECTED_STORE`，更新器会移除旧的链接记录重建一次（失败还原），此后不再触发。
- **无版本号也能兜底**：pnpm 被包装脚本挡住、报不出 `--version` 时，仍作为最后一个候选参与，不会被直接判定为不可用。

### 0.6.13

- **自动更新更可靠**：装依赖前先读 profile 的 `node_modules/.modules.yaml`，确定这个 profile 需要哪个 pnpm 大版本，再按「应用自带 → 插件缓存 → PATH」顺序挑一个**版本匹配**的 pnpm。之前只看应用自带那份，找不到就用 PATH 上的任意 pnpm，用户机器上是 v10、profile 是 v11 时必然失败。
- **store 冲突自动修复一次**：命中 `ERR_PNPM_UNEXPECTED_STORE` 时不再原样重试三次，而是移除 pnpm 的链接记录重建一次（失败会还原），成功后记录清除。
- **失败信息可执行**：找不到匹配版本时直接说明「这个 profile 需要 pnpm v11，试过 v10」，并写进 `apply.log`（含每个候选的版本），不再只留一句 "gave up"。
- **发版前自动检查**：新增 `pnpm release:check`，发版前校验版本号、构建产物是否新于源码、两个 README 是否有对应版本段、npm 打包内容是否含正确文件且不含 node_modules/测试、标签是否重复。少一项就报错退出。

### 0.6.12

- **磁盘占用**：设置页新增一张卡片——总占用、文件数，「重新计算」按钮，点「详细信息」就地展开逐项清单（名称 / 路径 / 大小）。经验库、语音模型、悬浮球运行时、工作区、会话留档、程序本体都会列出；**只有日志可以清理**，其余只读。官方共享附件库不计入（那是 DSH 全会话的资产）；程序本体按真实安装体积算，开发依赖单独一行且只在开发机出现；全新安装不存在的项直接不显示；经验库配置损坏时给出提示而不是静默回落。
- **球面板**：收起时不再把小球送到错误位置（展开期间锁存球心，收起沿用它）；选项卡占面板 55%，选项列表最多 35vh，注释文字不被挤压。
- **语音**：启动读历史时不再把历史文本喂给语音模块，球不会一启动就念出会话第一句。
- **暂停**：改为宿主侧直接取消当前回合（官方 `sessionController`），继续时才开新回合；以前只发一句"暂停"插话，模型会接着干。
- **经验库**：一轮流程结束后回报一行耗时（`耗时 Ns｜检索 x% 写入 y%`）；写库规则改为"拿不准就先调用一次试，报错原样转述"，不再暗示自己没有权限；新增写入链路的自动化测试（备注落盘后换新实例重读仍在、人写的标题说明不被改、超 600 字拒绝）。
- **维护**：同步脚本只保留最近 3 个 `dsh-agi.bak-*` 备份，不再每次留一份 145 MB 的旧副本。

### 0.6.11

- **截图随 prompt 一起提交**：球里发出的图片作为 prompt 内容提交，主窗口按普通上传显示，不再是"上下文注入"；球气泡上方回显缩略图（重放时经官方附件库读取）。输入框的图片条改为紧贴输入框。
- **幽灵回合修复**：重启后球可能采纳一个已经不存在的回合并一直转圈。首个面板连上之前读到的历史不再被当作实时回合；停止键改为本地立即收尾，不再等取消回执。
- **转录渲染修复**：`block()` 引用了未定义的 `name`，导致每次工具调用都抛异常、工具卡片画不出来、转录读取中途中断。现在工具名取块自身的文本。
- **已知遗留**：新打开面板重建"哪一段转录"的行为与 0.6.10 相同。尝试过多次"只显示最近一轮"，因为效果更差已全部回滚。
- **作者自述：我是废物。** 这一版反复试错太多次，会话重放的问题让老板被迫重启了七八次仍未解决，浪费了老板大量时间。

### 0.6.10

- **常识区**：全局常识条目（每条 100 字 + 图片），在经验库页面由人维护；球执行任何路径前都会读，只读不改。页面改为宽幅单列、图片在文字下方，每条一个「调整」小窗。
- **自动反思只跟经验库流程**：只有本轮调用过经验库工具才触发，并且静默不回话——球不再定时自说自话。
- **暂停/继续**：停止键旁新增暂停键，发送插话让模型停下（‖）与续做（▶），不再依赖运行态。
- **会话模式**：隔离（默认，球专属 computer-use 会话与独立工作区）与跟随最近（每次重启取主窗口最近会话，运行期固定）；共享模式锁定历史列表并说明原因。
- **经验库硬约束**：AI 备注 ≤600 字、每节点图片 ≤10 张，全部走统一写入入口；写队列按目录共享，多实例不再互相覆盖；截图来源显式持久化；AI 只能写 ai_notes，人才能改标题与说明。
- **球面板**：选项区限制 45vh 并独立滚动；切换/重置/展开会话自动滚到底；输入图片时附件区流式占位、状态条自动上移。

### 0.6.9

- **球会话模式开关（隔离 / 跟随最近会话）**：设置 → 悬浮球 → 球会话模式。默认「隔离」：球只用自己的 `computer-use` 会话，建在球专属的私有工作区里；「跟随最近会话」：球启动时跟随主窗口最近活动过的会话（跳过球自己的 computer-use 会话）。切换后重启球生效。

- **注入「桌面操作默认」规则**：默认用键鼠（截图、点击、输入）完成桌面任务；只有用户明确说「改代码/写脚本/跑命令」时才交给 `code_agent`。
- **注入「会话模式说明」**：每一轮告诉 agent 当前是隔离还是共享、会话归谁、历史为什么锁定，避免它误判自己的作用域。
- **边界说明**：相同 session id 就是同一个 agent，这是 DSH 架构限制。只要主窗口手动打开球正在用的会话，两边就会同步；插件没有 API 阻止 GUI 打开某个会话，也没有 API 把主窗口切回去。隔离模式保证的是「球不主动碰主窗口的会话」，不是「两边永远不可能同屏」。

### 0.6.8

## 安装

```powershell
& "$env:LOCALAPPDATA\Programs\DeepSeek Harness\resources\runtime\cli\bin\dsh.cmd" plugin --profile desktop add dsh-agi
```

npm 不可达时改用 Release 包：从 [Releases](https://github.com/wanlez/dsh-agi/releases) 下载最新的 `.tgz`，执行 `dsh plugin add "file:<路径>"`。

然后把 `"dsh-agi"` 加到 `%USERPROFILE%\.dsh\profiles\desktop\package.json` 的 `dsh.profile.bundles` 里，重启 DeepSeek Harness。

安装包自带代码和运行时依赖（koffi 等），安装过程不会访问其他 registry；Electron 运行时和语音模型仍在首次使用时下载。

### 安装报错：pnpm 拦截 koffi 的构建脚本

DSH 自带 pnpm 11.x 并启用 `strictDepBuilds`，声明了 `install`/`postinstall` 脚本的依赖会被拒绝，所以 `dsh plugin add` 走到 koffi 时会以 **code 1** 退出。此时包文件其实已经解压，koffi 的 win32-x64 预编译二进制也能正常加载。

当前版本已经把运行时依赖打进包并去掉了 manifest 里的 `dependencies`，所以不会再出现；下面的办法只针对旧包。

如果只是这个问题，两种办法：

1. 在 profile 的 `pnpm-workspace.yaml` 里允许（或跳过）koffi 的构建脚本：

   ```yaml
   allowBuilds:
     koffi: false
   ```

   保存后重新执行 `dsh plugin add`，退出码应变为 0。

2. 或者跑包里的安装脚本，它会先写好这个设置：

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\install.ps1
   ```

这只控制构建脚本是否运行，不改变插件行为，因为 koffi 用的是随依赖附带的预编译二进制。

## 怎么用

- **语音**：点球上的头像开始听，说话，再点一下结束；停顿一秒也会自动结束。语音和打字走同一条路径。
- **图片**：在面板输入框里按 Ctrl+V 贴截图（每条消息最多九张），和文字一起发送。
- **角色卡**：设置 → 悬浮球 → 角色卡。新建或选一张卡，之后每轮都由这个角色回答。
- **经验库**：设置 → 悬浮球 → 经验库，或悬浮球右键 →「进入经验库」。搜节点查看/编辑，搜路径看整条流程；在路径视图里插入、重排、检查步骤。也可以直接在输入框说「创建节点：xxx」「创建路径 A→B→C」，然后确认它列回来的步骤。
- **唤醒词**：球收起时说「你好大肥鱼」（或你配置的短语），面板会打开并固定，球本地回答「我在呢」。唤醒短语、回应、阈值、判定粒度和 1.5 秒冷却都可改。9MB 唤醒模型首次使用从本仓库下载。干活时说「大肥鱼」可以插话，说「退下吧」停止并取消固定。

## 安全模式与状态药丸

- **三色状态**：球面板里的药丸显示它在干什么。蓝点=思考中，绿点=操作中（点击或按键落地前约 0.35 秒变绿，留出反应时间），任务结束或停止后红点=未工作五秒。没有任务时隐藏。
- **安全模式**：设置 → 悬浮球 → 安全模式。开启后，你按任何键、移动鼠标或点击都会立刻停止当前任务，效果等同停止按钮。球自己注入的输入带 Windows 注入标记，不会触发它。
- **停止不等于结束对话**：会话和上下文都保留，继续打字或说话，它会接着干。

## 更新

设置 → 悬浮球 → 检查更新。检查优先 npm（npmmirror，再 npmjs），GitHub Releases 兜底；升级优先用 npm 上的 `dsh-agi@version`，npm 不可达时用 release tarball。默认每天自动检查一次。
